# Approve-чекпоинты — ABS Trainer iOS MVP v0.2

Документ фиксирует решения, которые требуют подтверждения пользователя перед переходом к следующему этапу.

## Статусы

- `approved` — подтверждено пользователем.
- `pending` — ожидает решения.
- `not_needed_now` — не требуется на текущем этапе.

## Чекпоинты

| ID | Решение | Статус | Комментарий |
|---|---|---|---|
| A1 | Scope MVP v0.2 | approved | Пользователь выбрал MVP v0.2. |
| A2 | Ускоренный план: iOS skeleton параллельно, placeholder 3D assets, упрощенный первый релиз | approved | Пользователь одобрил все пункты ускорения. |
| A3 | Способ установки | approved | Выбран Mac + Xcode + бесплатный Apple ID. TestFlight/Ad Hoc не используем на MVP. |
| A4 | Дизайн-направление Apple/Fitness-like | approved | Стиль выбран: Apple / Fitness-like. Финальный high-fidelity макет еще требует приемки. |
| A5 | Приемка high-fidelity макетов | pending | Нужен approve после показа финальных макетов. |
| A6 | Приемка первой рабочей сборки | pending | Нужен approve после запуска/демо MVP. |
| A7 | Финальные 3D-видео вместо placeholder assets | pending | Нужен approve по источнику/качеству/объему ассетов. |
| A8 | Финальная приемка MVP v0.2 | pending | Нужен approve после QA. |

## Правило для дейли

Каждый ежедневный отчет должен показывать:

1. Какие approve уже закрыты.
2. Какие approve ожидаются.
3. Какой ближайший approve нужен от пользователя.

## Ближайший approve

Сейчас ближайший содержательный approve: `A5 — приемка high-fidelity макетов`.
